## Rotate a provider credential

Rotate in place from the console's **Providers** page, or with
`PUT /v1/admin/providers/{id}`. The row keeps its id, slug, encryption context,
and custom pricing; the new credential is re-probed and re-encrypted. Warm
isolates pick it up within about a minute, which is also the tail on a deletion.

A gateway-routed instance owns no key of its own, so that call answers
`409 provider_gateway_managed`. Rotate the shared token once with
`POST /v1/admin/provider-gateways/{id}/rotate` and every instance behind that
gateway follows. See [Providers](/docs/providers).

## Reprice stored usage

`POST /v1/admin/apps/{app}/usage/reprice` recomputes stored `cost_usd` for one
provider type, model, and month. Each event is priced through the provider
instance that served it, falling back to the shipped catalog, so two instances of
one type can reprice the same model differently.

Run it as a dry run first (`apply: false`). The preview is tolerant: events whose
serving instance was deleted, and which no catalog price covers, are reported as
`unpriced_events` (with their current spend as `unpriced_cost_usd`) rather than
failing the call. `matched_events` counts only what would actually be rewritten.

`apply: true` is strict — if any matched event cannot be priced the whole call
answers `400 invalid_request` and nothing is written, so a month is never left
half-repriced. Clear the preview's `unpriced_events` first, either by re-adding
the missing custom price or by narrowing the month.

## Unresolved usage

Usage is read from the provider's own response. When a provider answers
successfully but reports usage in a shape this gateway does not know, there is
nothing to price: the request is served, the event is stored with no tokens, and
its cost is zero because nothing was measurable — not because nothing was spent.

Those events are marked `cost_source: "unresolved"` instead of `"computed"`, are
shown as **unresolved** rather than `$0.00` in the console's event list, and can
be counted with the **By cost source** breakdown. Each one also emits an
`error`-level `usage_unresolved_cost` log line naming the app, provider, model,
and route, so a new provider or a changed response format surfaces as an alert
rather than as free traffic. Live requests are never rejected for it.

A sustained count above zero means real spend is escaping the budget, and the
gateway cannot fix that on its own: the response shape has to be added to usage
extraction. Blocked requests never reached a provider and carry no
`cost_source`; events recorded before the field existed carry none either.

## Route attribution on usage events

Every event records the route it was actually sent over, which is known before
the request leaves: `provider_gateway_id` and `provider_gateway_type` name the
gateway that carried it and are null on a direct call, and `credential_source`
is `direct` for an instance holding its own key or `byok` when a gateway serves
it from your own key store. It is never inferred from a successful response, so
a null means nothing settled it rather than "probably yours".

`model_author` records who made the model, resolved when the event is recorded
so it can be grouped in SQL. It answers "how much Google-model spend, on any
route" — a question the provider type cannot, once one provider serves several
authors' models. It is an analytics dimension only: budgets and allowlists stay
per provider instance and per app.

`served_provider`, `served_model` and `reported_cost_usd` are for upstreams that
report what actually served a request and what it cost. No route reports them
yet, so they are null; `cost_usd` remains the billed figure either way.

Breakdowns by **model author**, **gateway**, and **credential source** are in the
console's usage view alongside the existing ones.

## Rotate the vault key

In `local` mode, add `SECRET_VAULT_LOCAL_KEK_V2` as a Worker secret and set
`SECRET_VAULT_LOCAL_KEK_CURRENT_VERSION=2`. Older versions stay accepted for
decryption, so existing blobs keep working and new writes use the new key; there
is no bulk re-encryption script yet, so keep the old version until every
credential has been rotated through the console. In `kms` mode, key rotation is a
cf-kms operation and does not touch this Worker.

Use Wrangler secret commands or stdin so no secret value enters shell history.

## Database migrations

Change `src/db/schema.ts`, generate a new Drizzle migration, and commit both the
schema and generated migration artifacts. Apply remote migrations through the
`DB` binding so deployments remain independent of a particular database name.

## Logs and traces

The Worker enables Cloudflare logs and sampled traces. Proxy responses also return
`Server-Timing` measurements for authentication, limit evaluation, and provider
time-to-first-byte.

## Health

`GET /v1/healthz` reports a non-secret `vault` field. `"misconfigured"` means the
`SECRET_VAULT_*` configuration is incomplete, contradictory, or invalid, and every
credential-touching request will answer `provider_unavailable`. The structured
`secret_vault_misconfigured` log line names the offending binding without
printing its value. Monitor this field after any secret change.
