---
title: Subscription check
description: Require that a signed-in user has paid before they can call AI providers through the app.
---

**Paid users only**, on the app's **Sign-in** tab, requires the user's sign-in
token to carry claims saying they have paid. It is available only with
**Signed-in users only**, because it needs a token to look at.

## How it works

The gateway never talks to the App Store. It checks claims inside the checked
sign-in token, and something else has to put them there after the purchase:

- **RevenueCat**, with its Firebase function kit, writes the user's active
  entitlements into their Firebase token as `revenueCatEntitlements`.
- **Your own server** can set any custom claim on your identity provider after
  it confirms a purchase.

### RevenueCat's Firebase function kit

The kit is a Cloud Function that runs in your Firebase project. RevenueCat
sends it every purchase event, and it writes the user's active entitlements into
the `revenueCatEntitlements` claim. To set it up:

1. Install the kit with the Firebase CLI, following RevenueCat's
   [Firebase function kit guide](https://www.revenuecat.com/docs/integrations/third-party-integrations/firebase-function-kit).
2. Set `SET_CUSTOM_CLAIMS` to `ENABLED`. It is off by default, and without it
   the token never carries the claim, so every paying user is refused.
3. Paste the deployed function's URL into the **Webhook URL** field of the
   Firebase integration in the RevenueCat dashboard.
4. Make a sandbox purchase, and check that the user's token carries the
   entitlement.

Each time a gateway token is issued, the gateway checks the sign-in token as
usual, then checks the required claims. A token without them is refused with
`403 issuer_claims_missing`.

## Choices

- **Any signed-in user**: signing in is enough. Payment is not checked.
- **Paid users only**: the sign-in token must carry the claims listed below.
  - **Add RevenueCat entitlement** adds the claim RevenueCat's function kit
    writes. Enter the entitlement's identifier from RevenueCat's Product
    catalog, not its display name. Several values admit a user who has any one
    of them.
  - A claim of your own is a row with a path into the token and what it must
    hold: **contains** matches a value in a list, or a word in a
    space-separated scope; an exact match compares the claim to one text,
    number or `true`/`false`.

## The waiting time

The claim is written after the purchase, by a webhook or a server job, and the
app may refresh its token before that has happened. For that time, a paying
user holds a valid token without the claim.

This is why the refusal has its own code. `issuer_claims_missing` means the user
is real and the entitlement has not arrived yet, so wait and try again. Treating
it as a failed sign-in would send the user round a loop they cannot get out of.

The gateway measures the wait. The app's **Errors** tab shows how long users
usually waited for the claim, and how many are waiting right now. See
[Auth events](/applications/auth-events).

## In the settings

The check is the `required_claims` list in the issuer settings. A RevenueCat
entitlement named `pro`:

```json
"required_claims": [
  { "path": "revenueCatEntitlements", "contains": "pro" }
],
"entitlement": "revenuecat"
```

A claim of your own, requiring a scope:

```json
"required_claims": [
  { "path": "scope", "contains": "ai.invoke" }
]
```

Each requirement has a `path` and exactly one of `contains` (a text or a list of
texts, any one of which may match) or `equals` (a text, a number or a boolean).
Every requirement must pass. `entitlement` only helps the console reopen the same
choice, and may be left out.
