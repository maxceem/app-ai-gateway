---
title: Model rewrites
description: Point a model name an app sends at the model the provider should receive.
---

An app's **Rewrites** tab maps a model name the app sends to the model the
provider receives. The app's **Models** list is checked against the name the
app sends, so the target need not be in it. The price, and the usage record, are
the target's.

A rewrite is how you move an app to a newer model without an app release: the
app keeps asking for `gpt-5.4-mini`, and you point that name at a newer model.
For a bigger change, such as another provider or fixed settings, use a
[preset](/applications/custom-endpoints).

To add one, click **Add rewrite**. Enter the model the app asks for in the first
box and the model to send in the second. Click **Save rewrites** to save. The
model sent must have a price, or saving is refused.

A rewrite applies on every connection, to calls through the provider proxy where
the request chooses the model and names that one. It does not apply where the
model is fixed by the path or the operation, nor to jobs, such as `fal.queue`:
those run the model they name. It is one step only: its target is never rewritten
again. Presets name their models themselves and are not rewritten.

## In the settings

```json
"routing": {
  "model_rewrites": { "gpt-5.4-mini": "gpt-5.4-nano" }
}
```

`model_rewrites` maps the model name an app sends to the one the provider
receives. Both are the provider's own model names. Leave it out for no
rewrites.
