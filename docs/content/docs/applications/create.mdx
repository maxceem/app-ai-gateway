---
title: Create an application
description: Walk through creating an iOS app or a server app, and what it creates.
---

Open **Apps** and click **New app**. The **Create an app** form asks one thing at
a time, and only what the kind of app you pick needs. Afterwards you can change
the app's name on its **Settings** tab. The **Sign-in** tab changes the sign-in
settings for the app's current kind; it has no choice of kind. The app's ID is
permanent.

## 1. Name and kind

- **Name**: how the app is listed. The gateway builds the app's permanent ID from
  it: `Calorie Tracker` becomes something like `calorie-tracker-k3f9x1`. See
  [The app ID is permanent](/how-it-works/apps-and-providers#the-app-id-is-permanent).
- **Where do calls come from?**: **iOS app** for calls straight from the app,
  proved with App Attest; **Server** for calls from your own server, with an app
  key it keeps secret.

## 2. How the app proves itself (iOS only)

Your **Apple Team ID**, your **Bundle ID**, and which builds to accept. See
[Application identity](/applications/auth-policy/identity#ios-apps).

## 3. Who may call

Whether calls belong to a user, and how the gateway knows who that is. See
[User authentication](/applications/auth-policy/user-authentication#the-choices).

## 4. Identity provider (signed-in users only)

Where your users sign in, from one or two values you already have. See
[Signed-in users only](/applications/auth-policy/user-authentication#signed-in-users-only).

## 5. Paid users only (signed-in users only)

Whether a user must have paid. See
[Subscription check](/applications/auth-policy/subscription-check).

## What is created

Click **Create app**. The new app is on, and has:

- no providers yet: it may call nothing until you allow a connection on its
  **Providers** tab;
- no limits, no model rewrites and no presets.

A server app also gets its first app key, shown once in a dialog titled **Copy
your app key now**. Copy it before you close the dialog: the gateway keeps only
a hash of it. You can make more keys later on the app's **Keys** tab.

Then you land on the app's **Overview** tab. Its **Ready to serve** section
says what is still missing, and **First requests** has example requests once a
provider is allowed. See [Provider access](/applications/provider-access).

## Through the API

`POST /v2/admin/apps` creates the same thing. The body has `name`, `config` and
an optional `status`, never an `id`. The answer has the app, with the ID the
gateway gave it in `app.id`, and for a server app its first key in
`api_key.key`.

A server app with no end users, allowed to call OpenAI's Responses API through
the `openai` connection:

```json
{
  "name": "Search service",
  "config": {
    "authentication": { "type": "api_key", "end_user": { "source": "none" } },
    "routing": { "providers": { "openai": { "operations": ["openai.responses"] } } }
  }
}
```

An iOS app with users who sign in with Firebase:

```json
{
  "name": "Calorie Tracker",
  "config": {
    "authentication": {
      "type": "apple_app_attest",
      "app_attest": { "team_id": "ABCDE12345", "bundle_id": "com.example.calorietracker" },
      "end_user": {
        "source": "issuer",
        "issuer": {
          "jwks_url": "https://www.googleapis.com/service_accounts/v1/jwk/securetoken@system.gserviceaccount.com",
          "issuer": "https://securetoken.google.com/my-app-1a2b3",
          "audience": "my-app-1a2b3",
          "user_id_claim": "sub",
          "required_claims": [],
          "max_token_lifetime_seconds": 86400,
          "provider": "firebase"
        }
      }
    }
  }
}
```

The configuration has five parts: `authentication`, `routing`, `limits`,
`presets` and `conversations`. Each is described on its own page in this
section: [Sign-in](/applications/auth-policy/identity),
[Provider access](/applications/provider-access),
[Model rewrites](/applications/model-rewrites), [Limits](/applications/limits),
[Presets](/applications/custom-endpoints) and
[Conversation history](/applications/conversations). All of them, field by
field, are in the
[app settings reference](/automation/agent-manual#application-configuration-reference).
