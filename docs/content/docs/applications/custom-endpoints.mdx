---
title: Custom endpoints
description: Keep the provider, model, parameters and fallbacks on the gateway behind a stable slug, so you can change them without an app release.
---

A custom endpoint is a URL of your own whose provider and model live in the
app's configuration instead of in the client:

```text
POST https://api.appaigateway.com/v1/apps/{app}/endpoints/{slug}
```

The client sends only the request body. You decide, and can change at any
time, which provider and model serve it, which parameters are fixed, and
what to fall back to when the provider fails. Custom endpoints ignore
provider access: this configuration is the policy.

## Adding one

On the app's **Custom endpoints** page, click **Add endpoint**. Every provider
type can serve one, in the request formats listed below.

- **Slug**: 1 to 64 characters from `a-z`, `0-9` and `-`. This is the last
  segment of the URL, so pick a name for what the endpoint does, such as
  `chat` or `transcribe`, not for the model behind it.
- **What it does**: text generation, image generation, speech (text to
  speech), transcription (speech to text) or embeddings. The model pickers
  only offer models of this kind, and the gateway refuses a model of another
  kind on save.
- **Request format**: the body your clients send. Only formats that carry the
  chosen kind, and that one of your providers serves, are offered.
- **Provider**: one of your providers, by slug, that serves the format.
- **Model**: swap it at any time; clients keep calling the same slug. Only
  models with a price are accepted, except where the provider reports its own
  cost for the format (xAI, OpenRouter): there **Other model ID…** takes any
  model it serves.
- **Parameters** (JSON formats): JSON deep-merged over the client body, with
  the server winning on conflicts. Leave `{}` for none. Use it for what every
  client should send, such as an image size or a voice.
- **Max output tokens** (text only): same rule as in provider access.
  A client value above it is refused, a missing value is injected.
- **Fallback chain**: provider and model pairs tried in order when the
  provider call fails, is rate limited upstream, or returns a server error,
  and nothing has been streamed to the client yet. Each provider attempt is
  recorded, including a failed attempt before a successful fallback. A
  fallback must speak the same format, so it can be another provider of the
  same type or any other provider that serves the format.

## Kinds and request formats

| What it does | Request format (`api_style`) | Providers |
| --- | --- | --- |
| Text generation | OpenAI Responses (`responses`) | OpenAI, xAI |
| | OpenAI Chat Completions (`chat_completions`) | DeepSeek, Groq, Mistral, Together AI, Fireworks AI, Cerebras, Moonshot AI, Hugging Face, Baseten, ByteDance, Perplexity, OpenRouter |
| | Anthropic Messages (`anthropic_messages`) | Anthropic |
| | Gemini generateContent (`gemini_native`) | Gemini |
| Image generation | OpenAI image generation (`image_generation`) | OpenAI, xAI, ByteDance (Seedream) |
| | Gemini generateContent (`gemini_native`) | Gemini image models (Nano Banana) |
| Speech (text to speech) | Gemini generateContent (`gemini_native`) | Gemini TTS models |
| Transcription (speech to text) | OpenAI audio transcription (`audio_transcription`) | OpenAI, xAI, Groq |
| Embeddings | OpenAI embeddings (`embeddings`) | OpenAI |
| | Gemini embedContent (`gemini_embedding`) | Gemini |

Each provider type serves a kind through one format, so a model of the right
kind on that provider always works in it. OpenAI and xAI text endpoints use
Responses, which every one of their text models supports.

Models that only work over a realtime connection, such as
`gpt-live-transcribe`, cannot serve a custom endpoint.

A provider routed through Vercel AI Gateway serves only Responses, Chat
Completions and Anthropic Messages endpoints, because those are the only APIs
Vercel publishes. OpenAI endpoints call `v1/audio/transcriptions`, xAI
endpoints call `v1/stt` and Groq endpoints call
`openai/v1/audio/transcriptions`.

## What the client sees

The request is authenticated exactly like a proxy request: a gateway token or
an API key, plus `X-App-Version` for token holders. Limits, usage accounting
and the error format are identical. The response keeps the serving provider's
own format and streams unbuffered. An unknown slug answers
`404 endpoint_not_found`. See [Calling custom endpoints](/integrate/endpoints).

## Fallback across keys

Because targets are addressed by provider slug, a fallback chain can name two
providers of the same type. `openai` falling back to `openai-dev` moves
traffic to a second key without changing the request shape. A fallback target
that cannot be resolved at request time, because the provider is gone,
disabled or unpriced, is skipped rather than failing the request. Only the
primary target must resolve, except that a disabled primary is skipped so its
fallbacks can serve. Deleting the primary provider, losing its credential, or
removing its price fails the request before fallback.

The whole chain shares a 120-second budget for response headers. A primary
that uses the entire budget leaves no time for a fallback; a stream that has
already begun is never restarted on another provider.

The **Usage** page's **By endpoint** breakdown shows what each endpoint cost,
and the event list shows which target served each request.

## In the configuration

```json
"endpoints": {
  "chat": {
    "api_style": "responses",
    "provider": "openai",
    "model": "gpt-5.6-luna",
    "params": { "reasoning": { "effort": "low" } },
    "max_output_tokens": 4096,
    "fallback": [{ "provider": "xai", "model": "grok-4.5" }]
  },
  "draw": {
    "api_style": "image_generation",
    "provider": "openai",
    "model": "gpt-image-2",
    "params": { "size": "1024x1024" }
  },
  "voice": {
    "kind": "speech",
    "api_style": "gemini_native",
    "provider": "gemini",
    "model": "gemini-3.8-flash-tts",
    "params": { "generationConfig": { "responseModalities": ["AUDIO"] } }
  },
  "transcribe": {
    "api_style": "audio_transcription",
    "provider": "openai",
    "model": "gpt-4o-mini-transcribe"
  }
}
```

`kind` is what the endpoint does: `text`, `image`, `speech`, `transcription`
or `embedding`. Most formats carry one kind, and the gateway fills it in.
`gemini_native` carries text, image and speech, so give it a `kind` unless the
endpoint generates text. A saved configuration always shows `kind`.

Every model in the block, fallbacks included, must be of the endpoint's kind
and have a price in the catalog or in that provider's custom pricing, or the
configuration is rejected on save. A model you price yourself counts as a text
model. A model with no price is accepted only on a provider that reports its
own cost, and that provider decides whether it serves it.
