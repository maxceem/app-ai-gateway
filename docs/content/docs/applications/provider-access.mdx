title: Provider access
description: Choose which provider connections, operations and models an app may use, and cap its output tokens.

An app's **Providers** tab decides which of your provider connections the app
may call, and what it may ask each one for. A new app may call nothing until
you allow a connection here.

The tab lists your connections, each with its name, its slug (the
`/proxy/<slug>/…` part of the URL) and its provider. Tick a connection to allow
it, then set what it allows. Click **Save providers** to save. A connection you
add later stays off for this app until you tick it here.

## Operations

An **operation** is one kind of request a provider serves, such as
`openai.responses` (OpenAI's Responses API), `openai.chat` (Chat Completions),
`anthropic.messages` or `gemini.generate.v1beta` (Gemini's `generateContent`).
Each connection lists the operations its provider has. Tick the ones the app
may use; at least one is required.

The gateway knows each operation's paths. A request on a path the gateway does
not know for this provider, or on an operation the app does not allow, is
refused with `403 path_not_allowed`.

Operations marked **live sessions, coming later** cannot be served yet. To start
a live session today, see [Passthrough](#passthrough) below.

A request that asks the provider to run in the background, with
`"background": true` or xAI's `"deferred": true`, is refused with
`400 invalid_request`. Its result and cost arrive only on a later poll, which
the gateway cannot serve.

To see every provider's operations, run `agw provider types`, or ask an agent
to call the `list_provider_types` tool.

### Passthrough

A connection can list **passthrough** paths: paths of the provider the gateway
has no operation for, such as OpenAI's `v1/files`, each with its method. An app
reaches them only if it allows the `passthrough` operation on that connection.
The gateway forwards such a request as it was sent:

- The app's sign-in, and its request limits, still apply.
- No model is read or checked, so the models list and model rewrites do not
  apply.
- The body is sent as the app sent it, unless the connection sets fixed fields
  on that path. Then the gateway reads the JSON body and writes those fields
  over the app's values.
- It is priced only if the path has a flat price per request. Without one, the
  call costs nothing in usage, and budgets do not stop it.
- It is never kept in [conversation history](/applications/conversations).

Some passthrough paths make a short-lived token for a live session, such as
OpenAI's `v1/realtime/client_secrets`:

- There is no operation to tick for them: the connection lists the path, and the
  app allows `passthrough`.
- The gateway checks the request that makes the token, and counts it against the
  app's request limits, like any passthrough call.
- It prices that request only if the path has a flat price. Without one, the
  request is recorded as `not_priced`, and the app's budgets do not apply to it.
- The live session itself then runs between your app and the provider directly,
  so what it spends is outside the app's budgets and usage.

To set one up:

1. On the **Providers** page, open the connection's actions and choose
   **Passthrough paths**.
2. Add one line per path, method first, such as `POST v1/realtime/client_secrets`.
   A price, such as `$0.002`, may follow. Click **Save paths**.
3. On the app's **Providers** tab, tick the `passthrough` operation on that
   connection, and click **Save providers**.

## Models

**Models** lists the models the app may use, separated by commas. Leave it empty
to allow every model that has a price. [Model rewrites](/applications/model-rewrites)
are applied after this check, so list the name the app sends. A request for
another model is refused with `403 model_not_allowed`.

Model names are the provider's own, exactly as the provider spells them:
`gemini-3.5-flash` on Gemini, never `google/gemini-3.5-flash`. Where the
provider's own names carry a prefix, keep it. That covers aggregators such as
OpenRouter (`openai/gpt-5.4-mini`) and Vercel AI Gateway, and providers whose own
model IDs have one, such as Together AI and fal.

A model needs a price, or the request is refused with
`400 pricing_not_configured`. The price can come from the price list or from your
own price on the connection, and must be in a unit the operation can bill: a
price in another unit is refused the same way. A provider that reports each
request's cost itself, such as OpenRouter for chat, needs no price.

Exceptions:

- A few operations take only priced models in their path, such as fal's
  `fal.run` and `fal.queue`. There, when the model sent has no price, the
  request is refused with `403 path_not_allowed` instead, even if you listed it
  in **Models**. On `fal.run`, a rewrite to a priced model works if the requested
  name passes the app's model list. `fal.queue` checks prices but does not apply
  rewrites.
- On other operations, a model you allowed whose price later disappears is still
  served, and its charge is recorded as `unresolved` until a price exists.

See [Model pricing](/providers/model-pricing).

## Most output tokens

Optional. When set, a request that asks for more output than this is refused
with `403 max_output_tokens_exceeded`, and a request that names no output limit
gets this value written in. It applies only to operations whose output is
counted in tokens; an image, an embedding or speech has none to cap.

## When a connection is missing

An app may name a connection you have since deleted. The app's **Overview** tab
shows it under **Ready to serve**. Requests to that slug are refused with
`502 provider_not_configured`, or `502 provider_disabled` for a connection you
turned off, and every other connection keeps working.

## In the settings

```json
"routing": {
  "providers": {
    "openai": {
      "operations": ["openai.responses", "openai.transcription"],
      "models": ["gpt-5.4-mini", "gpt-transcribe"],
      "max_output_tokens": 4096
    },
    "anthropic": { "operations": ["anthropic.messages"] }
  }
}
```

The keys of `providers` are connection slugs; a slug not listed is not allowed.
`operations` names at least one operation. `models` may be left out, which
allows every priced model. `max_output_tokens` may be left out.

A connection, operation or model you add is checked when you save. One that does
not exist, or a model with no price, is refused then, rather than when a
request arrives.
