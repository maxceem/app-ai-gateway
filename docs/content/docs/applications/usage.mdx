title: Usage and charges
description: Spend, tokens and provider attempts over time, with every charge in detail.
---

An app's **Usage** tab shows what the app has done. The **Apps** page sums the
same figures for the month across all your apps.

Every provider attempt is recorded as one **charge**: its model, tokens, cost and
outcome. A fallback chain records one charge per attempt. What a charge costs is
explained under [Where a cost comes from](#where-a-cost-comes-from).

## Daily usage by provider

A daily chart over the last 7, 30 or 90 days, by **Cost**, **Charges** or
**Tokens**, with one colour per provider.

## Breakdown

A table over the same days, grouped one way:

| Grouped | Answers |
| --- | --- |
| **By model** | Which models cost what |
| **By provider** | Which provider served the traffic |
| **By connection** | Which of your provider connections, for two keys of one provider |
| **By user** | Who spent what |
| **By install** | Which install spent what: one copy of an iOS app on one device |
| **By status** | Calls the provider served, and those that failed |
| **By price source** | Where each cost came from (see below) |
| **By measurement** | How the gateway measured the usage |
| **By operation** | Which kinds of request, such as `openai.responses` |
| **By preset** | Each [preset](/applications/custom-endpoints) |
| **By unit** | Tokens, images, seconds of audio and other units |
| **By app version** | The `X-App-Version` header, so you can see whether a problem is one release |

The columns are **Charges**, **Total input**, **Cached input**, **Cache write**,
**Output** and **Cost**. **Total input** counts every prompt token, including those
read from or written to the provider's prompt cache, so the two cache columns are
parts of it.

How far back each grouping reaches:

- **By model**, **By provider**, **By connection**, **By status** and **By unit**
  come from day totals, kept 400 days. They cover the whole range you choose.
- The other groupings are read from the charges themselves, which are kept 90
  days, and over at most 31 days at a time. With a longer range chosen, they show
  its last 31 days, and the table says so.
- Month totals are never lost.

## Recent charges

Every charge, newest first, with **When**, **User** (on an iOS app,
**User / install**), **Model**, **Operation**, **Tokens**, **Latency** and
**Cost**. Filter by status:

| Status | Meaning |
| --- | --- |
| `ok` | The provider answered with success |
| `provider_error` | The provider answered with an error |
| `timeout` | The provider did not answer in time |
| `network_error` | The connection to the provider failed |
| `client_aborted` | The app went away before the answer ended |

A request the gateway refused before calling a provider has no charge. Those
show as samples on the app's **Errors** tab. See [Auth events](/applications/auth-events).

## Where a cost comes from

- A call that fails before the provider answers usually costs nothing.
- A stream cut part-way can still be charged using the figures the gateway has.
  If it has no usage measure or reported cost, the cost stays unknown, though the
  provider may still charge for it.
- The gateway tries for about three days to price recorded usage that had no
  price yet. If no suitable price appears, the charge stays unpriced.

Each charge records its **price source**.

- `list_rate`: priced from the price list. The usual case.
- `customer_rate`: priced from your own price for the model on that connection.
  See [Model pricing](/providers/model-pricing).
- `provider_usd`: the provider said what the call cost, and that figure is used.
  OpenRouter does this, for example.
- `unresolved`: the gateway could not price the charge when it was made: it had
  no price that could bill the usage, or no usage to price. One with usage is
  priced on a later retry, if a suitable price appears while retries are still
  running. That adds a correction and keeps the original row, so
  `GET /v2/admin/apps/{app}/charges?price_source=unresolved` can still show
  charges whose cost was counted later.
- `not_priced`: a [passthrough](/applications/provider-access#passthrough) call
  with no price. The gateway reads no model there, so it has nothing to price.

Each charge also records how its usage was **measured**, shown as **By
measurement**:

- `complete`: nothing is missing. The usage was reported or measured in full, or
  there was none to measure.
- `partial`: the usage may be incomplete, for example because a stream ended
  early.
- `estimated`: the gateway had no usable usage report. It estimated the usage,
  or could not. A job's charge starts this way.
- `pending`: it waits for a later lookup.

## Through the API

- `GET /v2/admin/apps/{app}/usage` for the month's totals.
- `GET /v2/admin/apps/{app}/usage/timeseries` for the daily chart.
- `GET /v2/admin/apps/{app}/usage/breakdown?by=model` where `by` is one of
  `model`, `provider`, `connection`, `status`, `unit`, `user`, `install`,
  `operation`, `preset`, `price_source`, `measured` and `app_version`.
- `GET /v2/admin/apps/{app}/charges` for the charges, filtered by `status`,
  `provider`, `connection`, `model`, `user`, `install`, `operation`,
  `price_source` and more, and paged with `before`.
- `GET /v2/admin/usage` for the month across all your apps.
