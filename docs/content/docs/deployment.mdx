## Deploy to Cloudflare

The repository's deploy button is the shortest interactive path. Cloudflare forks
the repository, provisions the Worker and compatible bindings, applies migrations,
and connects subsequent pushes to Workers Builds.

Before starting, create a Cloudflare AI Gateway and an authenticated gateway token.
The form asks for:

| Value | Purpose |
|---|---|
| `CF_AIG_GATEWAY_ID` | The exact existing Cloudflare AI Gateway ID |
| `CF_AIG_TOKEN` | Its authenticated gateway token |

Provider API keys do not belong in these Worker secrets. Store them in Cloudflare
AI Gateway under **Provider Keys**, using alias `default`.

## Deploy with Wrangler

From a clean checkout:

```sh
pnpm install
cp .dev.vars.example .dev.vars
```

Fill the two required values without committing the file, then run:

```sh
pnpm run secrets:upload
pnpm run deploy
```

The deploy command preserves existing secrets, creates missing JWT and Better
Auth signing secrets, provisions D1 when necessary, applies migrations by binding name, and
deploys the console and API.

The public `wrangler.jsonc` intentionally has no custom production domain,
Cloudflare account-specific D1 database ID, or AI Gateway ID. Add a custom route
and the identifiers for resources you own in your private deployment
configuration. Keep `CF_AIG_GATEWAY_ID` and `CF_AIG_TOKEN` out of source control.

## Verify

Call the deployed health endpoint and then sign in to the console:

```sh
curl https://YOUR-WORKER.workers.dev/v1/healthz
```

Create the initial operator with `/v1/auth/sign-up/email`, then set
`ALLOW_PUBLIC_REGISTRATION=false` for a private deployment. Admin automation uses
organization-scoped `agw_mgmt_` keys created under `/v1/admin/keys`.

<Callout type="warn" title="Migration state is separate from Worker versions">
  A Worker rollback does not roll back D1. Review new migrations before deploying
  them to shared environments and never modify an applied migration.
</Callout>
