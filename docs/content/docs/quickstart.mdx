This page takes you from an empty console to a working request. It uses a
server app, because that is the shortest path: one key, one curl command. The
section on iOS apps, at the end, says where they stand.

Sign up at [console.appaigateway.com/v2/signup](https://console.appaigateway.com/v2/signup).
If the console asks you to verify your email address, open the link in the email
it sent. Until you do, your apps' requests are refused.

<Callout title="Self-hosting">
  Open your own console, and replace `https://api.appaigateway.com` in the
  examples with your gateway's API address.
</Callout>

Prefer a terminal or a coding agent? Follow the [CLI guide](/automation/cli) or
[Use with AI agents](/automation/agents).

## 1. Add a provider key

Open **Providers** and click **Add provider**.

- **Provider** is the service the key belongs to. This guide uses OpenAI.
- **Name** is how you tell your connections apart, for example `Prod OpenAI`.
- **Slug** is the short name your apps use in their URLs. Leave it empty to use
  the provider's own name, here `openai`.
- **API key** is the key you got from the provider.

Click **Test key** if you want the gateway to try the key first, then
**Add provider**. The key is encrypted on arrival and never shown again.

The first connection of each provider can take the provider's own name as its
slug. A second OpenAI key needs a slug of its own, such as `openai-dev`. See
[Add a provider key](/providers/add-a-provider).

## 2. Create an app

Open **Apps** and click **New app**. A short form asks one thing at a time.

1. **Name**: anything you like. The gateway builds the app's ID from it, for
   example `example-app-a1b2c3`.
2. **Where do calls come from?**: choose **Server**.
3. **Who may call**: choose **No end users** for now. You can change it later
   on the app's **Sign-in** tab.
4. Click **Create app**.

A dialog titled **Copy your app key now** shows the app's key. It is shown only
this once: the gateway keeps only a hash of it. Copy it and keep it somewhere
safe. You can make more keys later on the app's **Keys** tab.

## 3. Allow the provider

A new app may call nothing yet. You choose what it may call.

Open the app's **Providers** tab and tick your `openai` connection.

- **Operations** are the kinds of request the app may send. Tick
  `openai.responses`, OpenAI's Responses API, which this guide uses. Others,
  such as `openai.chat` for Chat Completions, can be added later.
- **Models** limits the app to the models you list. Leave it empty to allow
  every model that has a price.

Click **Save providers**. The app's **Overview** tab now shows it is ready to
serve.

## 4. Send a request

The **Overview** tab's **First requests** section has example requests for
this app, ready to copy. Or put the key in an environment variable and call
OpenAI's Responses API through the gateway. Replace the app ID with yours.

```sh
export APP_AI_GATEWAY_KEY="agw_…"

curl https://api.appaigateway.com/v2/apps/example-app-a1b2c3/proxy/openai/v1/responses \
  -H "Authorization: Bearer $APP_AI_GATEWAY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"gpt-5.4-mini","input":"Say hello."}'
```

The answer is OpenAI's own, unchanged. Everything after `/proxy/openai/` is the
path OpenAI documents, and the body is the body OpenAI documents. The gateway
added your provider key on the way out and recorded the call on the way back.

If you use an SDK instead of curl, point it at the gateway and keep everything
else:

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["APP_AI_GATEWAY_KEY"],
    base_url="https://api.appaigateway.com/v2/apps/example-app-a1b2c3/proxy/openai/v1",
)
```

## 5. See it in the console

Open the app's **Usage** tab. The call is in **Recent charges** with its model,
tokens and cost, and **Daily usage by provider** shows the day's spend. The
**Apps** page shows this month's spend across all your apps.

## If something failed

| Answer | What it means |
| --- | --- |
| `403 email_unverified` | Your account's email address is not verified yet. Open the link in the verification email, or send a new one from the console. |
| `401 auth_required` | The key is missing or wrong. |
| `502 provider_not_configured` | The app does not allow a connection with the slug in the URL. Tick it on the app's **Providers** tab. |
| `403 path_not_allowed` | The app does not allow this operation, or the path is not one the gateway knows for this provider. |
| `403 model_not_allowed` | The model is not in the app's **Models** list. |
| `400 pricing_not_configured` | The model has no price, so the gateway cannot count its cost. Use a model on the price list, or add a price for it. |
| An error in OpenAI's own format | The request reached OpenAI, and OpenAI refused it. If it says the key is invalid, check the provider key you added in step 1. |

The full list is in [Errors and limits](/integrate/errors).

## iOS apps

An iOS app has no key to ship. It proves it is a real install of your app with
Apple App Attest, and the gateway gives it a short-lived token. To create one,
choose **iOS app** in step 2 and enter your **Apple Team ID** and **Bundle ID**.

Today you can create and set up an iOS app here, and the gateway serves App
Attest sign-in for it. The Swift package that does that sign-in for you is coming
with the v2 SDK; until then, the iOS integration guide and the demo app still
describe the earlier version.
