title: Model pricing
description: Where the gateway's prices come from, how to add your own, and which providers report their own cost.
---

The gateway counts what each request costs, so your apps' budgets and usage
stay right. To count it, the model needs a price, or the provider must report
the cost itself. An ordinary model call for a model with neither is refused
with `400 pricing_not_configured` before it reaches the provider. On fal, whose
paths name the model, it is `403 path_not_allowed` instead. The exception: a
model the app lists by name, or a preset's primary model, keeps being served if
its price later goes away. That does not hold on fal, where a model needs a
price even when the app lists it by name. See [Models](/applications/provider-access#models)
for the rules.

A price comes from one of three places, in this order:

1. the cost the provider reports in its answer, where it reports one;
2. [your own price](#your-prices) for the model on that connection;
3. the gateway's [price list](#the-price-list).

What each charge was priced from, and what happens when nothing could price it,
is explained in [Where a cost comes from](/applications/usage#where-a-cost-comes-from).

## The price list

The gateway comes with a price list: what each model costs, by provider and the
provider's own model ID. It is market data, not something you set, so it
changes with the gateway. Self-hosted gateways get changes when you update
your deployment.

You can read it in three places:

- the console's **Prices** page, with a filter;
- `GET /v2/admin/prices`;
- the file `/v2/models.json` beside the console, such as
  [`https://console.appaigateway.com/v2/models.json`](https://console.appaigateway.com/v2/models.json).
  Any web page may read it.

The **Prices** page shows, for each model, its **Provider**, **Kind**,
**Input** and **Output** prices, **Other rates** and **Notes**. Input and output
are in dollars per million units: tokens for text models, and the model's own
unit for the rest. Other rates are per second, minute, hour, image, video,
request, or the provider's own billed unit. A model with a higher price for
long prompts shows both.

### What an entry holds

The file is grouped by provider, then model ID. The fields you are most likely to
read:

| Field | Meaning |
| --- | --- |
| `kind` | What the model does, such as `text`, `image`, `speech` or `transcription`. |
| `input`, `output` | Dollars per million input and output tokens. |
| `cached_input`, `cache_write` | Input read from, or written to, the provider's prompt cache. Without them, these tokens are priced at `input`. |
| `long_context_threshold`, `long_*` | A prompt longer than the threshold has all its tokens priced at the `long_` prices. |
| `per_minute`, `per_hour`, `per_image`, `per_million_characters`, … | Prices in other units, for models priced that way. |
| `modes` | Prices in other [service modes](#service-modes). |
| `retirement_date` | The day the provider stops serving the model. |
| `unlisted_since` | The day the provider's price page stopped listing the model. |
| `price_changes` | Price changes the provider has announced, each with the day it starts. |

A price is never removed. A model the provider stops listing keeps its last
price, marked `unlisted_since`, so an app that still uses it keeps being charged
correctly. When an app uses a model that is retiring or no longer listed, its
pages show a notice titled **A model this app uses is leaving our price list**.

Some providers have no price list here:

- **Fireworks AI** and **Hugging Face**, whose prices differ by account or
  route: add your own prices.
- **OpenRouter**, which reports each request's cost.
- **Vercel AI Gateway**, whose models are priced under their maker. See
  [Vercel AI Gateway](/providers/gateways#model-names-and-prices).
- **Custom providers**, which use only your prices.

The prices estimate the provider's bill from the usage it reports. Discounts
and charges a provider does not report in its usage are not in them. Check the
provider's own bill when you need the exact amount.

## Your prices

Your prices are for a model the price list does not have, or to replace a
listed price. They belong to one connection: a model priced only there works
through that connection alone.

Open **Providers**, open the connection's actions, and choose **Your prices**.
Click **Add a model** for each model and fill in:

| Field | Meaning |
| --- | --- |
| **Model** | The model ID exactly as your app sends it. |
| **Input $/1M**, **Output $/1M** | Dollars per million input and output tokens. Set both, or neither. |
| **Cached input $/1M** | Optional. Input read from the provider's prompt cache. |
| **Unit rate $** and **Unit** | Optional. A price in another unit, such as per image, per minute, per request or job, or per million characters. |

Click **Save prices**. **Edit as JSON** shows every field a price can hold,
including ones the form does not show; fields the form does not show are kept
as they are.

Your price replaces the list's price for that model on that connection. It does
not borrow any of the list's rates, except its service mode factors (see below):
a rate you leave out is priced as it would be on an entry without it. So if the provider gives a cache discount, enter it, or
cached tokens are priced at the full input price.

The same through the API. `pricing` replaces all your prices on the connection,
and `null` removes them. For a model on an OpenAI connection:

```http
PUT /v2/admin/providers/{id}
Content-Type: application/json

{
  "pricing": { "my-model": { "input": 1.25, "output": 10, "cached_input": 0.125 } },
  "revision": 7
}
```

Each price must suit the connection's operations, so a price per job goes on a
fal connection instead: `{ "fal-ai/some-model": { "per_request": 0.02 } }`.

`pricing` takes the same rate names as the price list. Two more fields:

- `modes`: your prices in other service modes. Without it, the list's mode
  factors for that model apply to your rates.
- `by`: rates that depend on a request field, such as an image's size:
  `{ "size": { "1024x1024": { "per_image": 0.04 } } }`.

Saving checks every price:

- A price none of the connection's operations could charge, such as a per-image
  price on a text-only provider, is refused with `400 invalid_request`.
- On a provider that runs [jobs](/applications/jobs), such as fal, each model
  takes exactly one unit rate, because a job settles at the rate it started with.
- The gateway checks the affected calls your active apps can still make. If it
  can't price one fully, the save is refused with `400 pricing_not_configured`. See
  [Changes are checked against your apps](/providers/add-a-provider#changes-are-checked-against-your-apps).

Removing a connection removes your prices on it. Charges already recorded keep
their cost.

### Free models

`$0` is a valid price, for a model you run yourself and pay nothing per request
for. Its requests still count toward request limits, but add nothing to
any budget. Enter it on purpose.

## Providers that report their own cost

Some answers say what the provider charged, and that figure is charged as it is.
Those models need no price.

| Provider | Answers that report a cost |
| --- | --- |
| xAI | Chat Completions, Responses, legacy completions, and images |
| OpenRouter | Chat Completions, the only operation it has |
| ElevenLabs | Speech to text |

Their other operations, such as xAI's Messages API, use prices.

A reported cost comes through a direct connection and through Cloudflare AI
Gateway. It does not come through Vercel AI Gateway, which answers in its own
format.

If an answer that should report a cost comes without one, your price or the
list's is used if there is one. Otherwise the charge is marked `unresolved`.

## Service modes

Some providers sell a model in more than one **service mode**:

- a tier, such as `flex` (cheaper, may wait), `priority` or `fast` (dearer,
  served first);
- a region the request is kept in, such as `us` or `eu`;
- or both, such as `priority+eu`.

A model's entry lists the modes it is sold in under `modes`, usually as a factor
of the standard price:

```json
"modes": { "flex": { "factor": 0.5 }, "fast": { "factor": 2 } }
```

A request is priced in the mode that served it. That is the mode the provider's
answer names, where it names one, or else the mode the request asked for, in the
provider's own field, such as OpenAI's `service_tier` or Anthropic's `speed`. A
connection whose base URL is a regional host, such as `https://us.api.x.ai/`,
is priced in that region.

A request is never refused because its mode has no price. It is served and
priced at the closest known price, never below the standard price, and marked
as an estimate: `price_is_estimate` on the charge, and **≈** before its cost in
the console. To price it exactly, add that mode to your price. A
[preset](/applications/custom-endpoints) that sets a mode with no price is
refused when you save it.
