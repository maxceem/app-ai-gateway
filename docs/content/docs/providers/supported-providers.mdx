Every connection has a provider. The provider fixes the host, the header the
key is sent in, the operations an app can allow, and the prices it is looked up
in. The path after the slug is always the provider's own path, without a
leading slash:

```text
/v2/apps/{app}/proxy/{provider}/{provider_path}
```

For every provider's full list of operations, run `agw provider types`, or call
`GET /v2/admin/provider-types`.

**Test key** is explained in [Add a provider key](/providers/add-a-provider#test-key).
A provider with no test call has no free call that proves a key: its list of
models is public, needs an ID the key does not carry, or does not exist.

**Through Cloudflare** says whether the connection can go through your
Cloudflare AI Gateway. See [Cloudflare and Vercel AI Gateway](/providers/gateways).

### Paths kept from the earlier gateway

Most providers also accept paths the earlier version of the gateway accepted
for every provider, so apps built for it keep working. They are Chat
Completions, Responses, Messages and transcription at the common layouts, such
as `v1/chat/completions`, `chat/completions` and `v1/messages`. Which of them a
provider has varies: OpenRouter has the Chat Completions ones only, Vercel AI
Gateway has no transcription, and ElevenLabs, Deepgram and fal have none.
Each is an operation of its own, named after its kind, such as
`anthropic.chat` or `deepseek.messages.v1`, so an app allows it like any other.
`agw provider types` lists each provider's operations.

Use the provider's own paths from the table in new code. A path the provider
itself does not serve is sent to it anyway, and the provider answers it with
its own error.

## Using an SDK

Point the SDK's base URL at the connection, up to the provider's version
prefix, and give it your app key or gateway token where it expects the
provider's key. The SDK adds its own paths.

| SDK | Base URL |
| --- | --- |
| OpenAI | `https://api.appaigateway.com/v2/apps/{app}/proxy/openai/v1` |
| Anthropic | `https://api.appaigateway.com/v2/apps/{app}/proxy/anthropic` |
| Groq, through the OpenAI SDK | `https://api.appaigateway.com/v2/apps/{app}/proxy/groq/openai/v1` |
| DeepSeek, through the OpenAI SDK | `https://api.appaigateway.com/v2/apps/{app}/proxy/deepseek` |

Request bodies and answers keep the provider's own format. See
[Calling the provider proxy](/integrate/proxy).

## Before you add a key

**Paths differ.** Groq puts its OpenAI-style API under `openai/`. DeepSeek and
ByteDance Ark have no version prefix. Fireworks AI serves inference under
`inference/v1/`. Copy the path from the table rather than assuming `v1/`.

**Gemini** has two APIs. Its own `generateContent` names the model in the path.
Its OpenAI-style API is at `v1beta/openai/chat/completions`. Both work directly
and through Cloudflare AI Gateway.

**ByteDance Ark** is BytePlus ModelArk in the `ap-southeast` region, with its
version already in the host's address. Keys and models are kept apart by region,
and a model must be turned on in your ModelArk console before it answers. For
another region, set a [base URL](/providers/custom-base-urls).

**Moonshot AI** uses the international host, `api.moonshot.ai`. For a key from
the China platform, set the base URL to `https://api.moonshot.cn/`.

**Regional hosts.** xAI's `us.api.x.ai`, Mistral's `api.eu.mistral.ai` and
`api.us.mistral.ai`, and Together AI's `us-api.together.ai` cost more than the
global host. Set one as the connection's base URL, and its requests are priced
at that region's price. See [Service modes](/providers/model-pricing#service-modes).
OpenRouter's in-region hosts are set the same way, with their API path:
`https://eu.openrouter.ai/api/` or `https://us.openrouter.ai/api/`.

**Fireworks AI and Hugging Face** have no price list here. Fireworks names
models per account, and Hugging Face prices one model differently on each
service it routes to. Add [your own prices](/providers/model-pricing#your-prices)
for the models you use. On Hugging Face, name the service in the model ID
(`author/model:service`) and price that ID, so the price matches what you pay.

**OpenRouter** serves Chat Completions only, because only those answers report
what OpenRouter charged. Its model IDs carry the model's maker, such as
`openai/gpt-5.4-mini`, and that is the name to allow and send. Each request is
charged at the cost OpenRouter reports, so its models need no price. When a
request runs on your own provider key added in OpenRouter, the cost is
OpenRouter's fee plus the provider's cost it reports: both came out of your
accounts.

What your app's model list checks on OpenRouter:

- `model`, as the request sends it, and each model in a `models` fallback
  list. On a custom Messages path to OpenRouter, `fallbacks` is checked the
  same way. Each must be on your list. The request is charged as the model
  that answered. A `models` list sent with no `model` must start with a model
  that can be billed, since OpenRouter tries it first.
- A router such as `openrouter/auto`, or a saved preset as the model
  (`@preset/...`), is a model name like any other. When your app lists its
  models, it's served if the list names it and refused if it doesn't. When
  your app lists no models, it's served. A target of one of your app's rewrites
  is your choice too, and is served.

What is passed through as it is, with no check: a `preset` field, plugins
such as Fusion, and server tools such as an advisor, a subagent or image
generation. These OpenRouter features can call other models, also ones
your list doesn't name. On the built-in OpenRouter connection, those calls
are part of the cost OpenRouter reports for the request, which is what the
request is charged, and they count toward your app's spending limits like
any other cost. A custom path to OpenRouter is charged at the prices you
set for it instead, from the tokens its answer reports, so it may leave out
what those extra calls cost.

**Perplexity** has two kinds of model name, served at different paths:

- Its own Sonar names, such as `sonar-pro`, at `chat/completions` and
  `v1/sonar`.
- Names that carry the model's maker, such as `openai/gpt-6.2-sol` or
  `perplexity/sonar`, on its Agent API (`v1/agent`, or `v1/responses` for
  OpenAI's SDKs) and its Orchestrator API (`orchestrator/v1/`).

A few models are on one of the two only: `perplexity/sonar` is on the Agent
API only, `openai/gpt-5.4-mini` on the Orchestrator API only.

A preset fallback that names no operation goes to the path that serves its
model's name: Sonar's for a Sonar name, the Orchestrator API for Chat
Completions or Messages, and the Agent API for Responses, unless only the
Orchestrator API serves the model. A preset whose model
no path of its kind serves, or that names an operation that does not serve its
model, is refused when you save it.

Every model a request names must be one the app allows, with a price: its
`model`, after your model rewrites, each entry of the Agent API's `models`
list, and the `routing.default_model` and each route's `model` on the
Orchestrator API. The charge is for the model that served the request.

- The Agent API tries `models` before `model`, and a request may send the list
  without `model`.
- An Agent API `effort` or `profile` can bring a `models` list of its own. A
  request that sends one with `model` and no `models` list is sent with
  `models` set to that one model, so Perplexity uses only the model checked.
- A request that spells one of these fields in another letter case, such as
  `Model` or `ROUTING`, is refused: Perplexity may read it as the field.
- A request that names no model is refused, because Perplexity would choose
  one. That includes an Agent API `effort` or `profile` sent with no `model`
  or `models`. `perplexity/auto` with a `routing` block is charged as the
  model that answered. With no `routing` block, it is served at your price
  for it when your app lists it, one of your app's rewrites names it, a
  preset names it, or your app lists no models; when a request names it and
  your app lists other models only, it is refused.

One-hour cache writes on the Orchestrator API (`prompt_cache_options.ttl:
"1h"`, or `cache_control` on Messages) are charged at the one-hour rate.

Sonar and the Agent API report what each request cost, including Sonar's
request fee and the Agent API's tools such as web search, and that figure is
what is charged. Perplexity rounds it to five decimals, so a very small
request can read $0. When a figure under $0.001 is less than Perplexity's own
price for the request, Perplexity's price is charged instead, marked as an
estimate. For a model with no price, such a
figure is treated like a missing one. An answer without the figure is charged
at the model's price, marked as an estimate. If the model has no price, the
request's cost is left unknown until you add one. This applies to every
provider that reports its own cost.

**xAI** reports what each Chat Completions, Responses, legacy completions and
image request cost, and that figure is what is charged. Its Messages API,
embeddings and `v1/stt` use prices, like any other provider.

**ElevenLabs.** Text to speech names the voice in the path and the model in
the body's `model_id`, with `eleven_multilingual_v2` when it names none. It is
charged by the characters of the request's `text`. Speech to text is an upload,
charged at the cost ElevenLabs reports, or else by the audio's length.

**Deepgram.** `v1/listen` takes the audio as the request body, or JSON with a
`url`. The model and every option are query parameters, such as
`?model=nova-3&language=multi`. With no model, Deepgram uses `base-general`,
which has no price in the list, so it is served only with your own price.
Options Deepgram charges extra for, such as redaction, are charged on top. A
request may take up to 20 minutes before Deepgram answers.

**fal.** `run/{model}` is a call that answers when it is done.
`queue/{model}` submits a job your app checks on later: see
[Jobs](/applications/jobs). The model ID is part of the path, such as
`run/fal-ai/flux/dev`, and only priced models match it. A model without a price
is refused with `403 path_not_allowed`.

**Vercel AI Gateway** serves many providers' models through one key. See
[Vercel AI Gateway](/providers/gateways#vercel-ai-gateway).

**Live sessions.** OpenAI Realtime (`openai.realtime`), xAI voice
(`xai.realtime`) and Gemini Live (`gemini.live.v1beta`, `gemini.live.v1alpha`)
run through the gateway's relay. See [Live sessions](/integrate/live-sessions).
For other live APIs, list the provider's token path for passthrough, such as
ElevenLabs' conversation token paths. The gateway fills in safe settings for
these, such as a short expiry. See
[Passthrough](/applications/provider-access#passthrough).

## Images

Image models work through the image operations in the table, as long as the
model has a price the gateway can charge:

- OpenAI's GPT Image and Gemini's image models are priced per token, with
  images at their own rate. Call Gemini image models on `generateContent`: its
  answer says which tokens were images.
- ByteDance's Seedream models are priced per image, by the images the answer
  counts.
- xAI's image models are charged at the cost xAI reports.

Other image models, such as Together AI's, are not in the price list. You can
serve one with [your own price](/providers/model-pricing#your-prices), such as
a price per image. The [Prices](/providers/model-pricing#the-price-list) page
shows which image models are listed.

Image generation inside another model's request, such as the Responses API's
`image_generation` tool, is charged only for the calling model's tokens. To
count images, call the image operation directly.
