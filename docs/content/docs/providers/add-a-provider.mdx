---
title: Add a provider key
description: Add a provider key once as a connection, test it, and change, turn off or remove it later.
---

You bring your own provider keys. Each key you add is a **provider
connection**: the key, the provider it belongs to, and a slug your apps use in
their URLs. Every app you have can use a connection, once you allow it on the
app's [Providers tab](/applications/provider-access).

The gateway encrypts a key when it arrives and never shows it again. The
**Providers** page shows only its last characters, so you can tell two keys
apart.

## Add a connection

Open **Providers** and click **Add provider**. The dialog, **Add a provider**,
asks for:

| Field | What to enter |
| --- | --- |
| **Provider** | The service the key belongs to. See [Supported providers](/providers/supported-providers). |
| **Name** | How you tell connections apart, for example `Prod OpenAI`. Up to 100 characters. |
| **Slug** | The name your apps use in their URLs. Leave it empty to use the provider's own name, such as `openai`. See [Slugs](#slugs). |
| **Send through Cloudflare AI Gateway** | Shown for providers Cloudflare can carry. See [Cloudflare and Vercel AI Gateway](/providers/gateways). |
| **Base URL (optional)** | Leave it empty to use the provider's own host. Fill it to send requests to another host, such as a self-hosted server or a regional host. Hidden while Cloudflare is on. See [Custom base URLs](/providers/custom-base-urls). |
| **Base URL**, **Key header**, **Key format** | For a **Custom provider** only. See [Custom providers](/providers/custom-base-urls#custom-providers). |
| **API key** | The key from the provider. |

Click **Test key** if you want the gateway to try the key first. Then click
**Add provider**. Saving never calls the provider, so a provider outage, or a
key that is not live yet, does not stop you from saving.

A key is at least 8 characters, with no quotes, backslashes or control
characters. The **API key** field empties itself when you change where requests
go, such as the provider, the base URL or the Cloudflare IDs. A key is only
ever sent to the place you typed it for, or back to the provider's own host when
you ask for that.

The same through the API:

```http
POST /v2/admin/providers
Content-Type: application/json

{ "type": "openai", "name": "Prod OpenAI", "secret": "sk-…" }
```

The body takes:

- `type` and `name`, which are required;
- `slug`, which defaults to `type`;
- `secret`, the provider's key, required unless the connection goes through
  Cloudflare AI Gateway;
- `baseUrl` or `cloudflareGateway`, to change where requests go;
- `pricing`, your own [prices](/providers/model-pricing#your-prices);
- `passthrough`, [listed paths](/providers/custom-base-urls#listing-paths);
- `servingProviders`, for [Vercel AI Gateway](/providers/gateways#vercel-ai-gateway) only;
- `auth`, for a [custom provider](/providers/custom-base-urls#custom-providers) only.

The answer is `{ "provider": { … } }`: the connection, with `secretHint`, the
key's last characters.
It never holds the key. `GET /v2/admin/provider-types` lists every `type`
with its operations.

## Test key

**Test key** sends the provider one free request that needs a valid key, such
as listing its models, and nothing else. It goes to the same host your apps'
requests would use, through Cloudflare AI Gateway too if you turned it on.
Nothing is stored.

| Answer | Meaning |
| --- | --- |
| The provider accepted this key. | The test call worked. |
| The provider refused this key. Check it, unless it is restricted so it cannot list models. | The provider answered `401`. Usually the key is wrong. A key restricted so it cannot list models can get the same answer. |
| This provider has no free call to test a key with. You can still save it. | Nothing was sent. See [what each test calls](/providers/supported-providers#all-provider-types). |
| The provider did not answer in time, so the key is not proven. You can still save it. | No answer within 4 seconds. |
| The provider answered …, which proves nothing either way. You can still save it. | Any other status, `403`, `404` and `429` included. |

Only the second answer suggests the key is wrong. The last three prove nothing, so
add the key if you know it is right.

The same through the API, with the fields the connection would have:

```http
POST /v2/admin/providers/test
Content-Type: application/json

{ "type": "openai", "secret": "sk-…" }
```

It takes `type`, `secret`, `baseUrl`, `cloudflareGateway` and `auth`, and
answers `validated`. When that is `false`, `reason` is `rejected`, `no_probe`,
`unreachable` or `unexpected_status`. `rejected` and `unexpected_status` also
carry the provider's `status`.

## Slugs

The slug is the `{provider}` part of your apps' URLs:

```text
/v2/apps/{app}/proxy/{provider}/{provider_path}
```

It is 1 to 63 characters: lowercase letters, digits and `-`, starting with a
letter or a digit.

You can add as many connections of one provider as you like: a second OpenAI
key for development, one through Cloudflare AI Gateway, one at your own host.
Each slug is used once in your account, so only one of them can be `openai`.
Give each other one a slug of its own:

| Connection | Slug | Your app calls |
| --- | --- | --- |
| OpenAI, first key | `openai` | `/v2/apps/my-app/proxy/openai/v1/responses` |
| OpenAI, development key | `openai-dev` | `/v2/apps/my-app/proxy/openai-dev/v1/responses` |
| OpenAI through Cloudflare | `openai-cf` | `/v2/apps/my-app/proxy/openai-cf/v1/responses` |

A slug already in use is refused with `409 conflict`. A connection keeps its
slug while it exists, turned off or not. Removing it frees the slug.

The provider, and with it the host, the key header and the prices, always comes
from the connection the slug names, never from the URL.

## The Providers page

Each row shows the **Name**, the **Provider**, the **Slug**, the **Key** (its
last characters, and "via Cloudflare AI Gateway" where that is on), the
**Status** (**On** or **Off**) and when it was **Updated**.

The row's actions:

- **Rename**: changes the name only. Apps keep calling the same slug.
- **Replace key**: see [Replace a key](#replace-a-key).
- **Passthrough paths**, or **Paths** on a custom provider: see
  [Listing paths](/providers/custom-base-urls#listing-paths).
- **Your prices**: see [Model pricing](/providers/model-pricing#your-prices).
- **Host**: where requests go. See [Custom base URLs](/providers/custom-base-urls).
- **Cloudflare AI Gateway**: see [Cloudflare and Vercel AI Gateway](/providers/gateways).
- **Turn off** or **Turn on**.
- **Remove**.

## Replace a key

**Replace key** puts a new key in place of the old one. Apps using the
connection usually switch to the new key within a minute. See
[When changes take effect](/how-it-works/apps-and-providers#when-changes-take-effect).
The slug, the name and
your prices stay, so nothing in any app changes. Prefer it to removing the
connection and adding it again.

Paste the **New API key**, click **Test key** if you like, then **Replace key**.
On a connection through Cloudflare AI Gateway there is no **Test key** here.

```http
PUT /v2/admin/providers/{id}
Content-Type: application/json

{ "secret": "sk-new…", "revision": 7 }
```

Every change through `PUT` sends the connection's `revision`, which every
answer about a connection carries. Send the one from your last read. If someone else saved it since, the change is refused with
`409 conflict`; read it again and retry. The console shows this as **This
connection changed since you opened it**, with a **Reload** button.

## Turn off or remove

**Turn off** pauses a connection. The key, the slug and your prices all stay.
Requests to its slug are refused with `502 provider_disabled`. **Turn on** brings
it back, usually within a minute.

```http
PUT /v2/admin/providers/{id}
Content-Type: application/json

{ "status": "disabled", "revision": 7 }
```

**Remove** deletes the connection, its key and your prices on it. Apps that
name the slug usually stop reaching the provider within a minute, and are
refused with `502 provider_not_configured`. Their settings keep the slug, so a
new connection with the same slug serves their new requests. Jobs started on
the removed connection stay with it: checking on them answers
`404 job_not_found`.

```http
DELETE /v2/admin/providers/{id}
```

An app's **Overview** tab shows a connection it names that is turned off or
missing. See [When a connection is missing](/applications/provider-access#when-a-connection-is-missing).

## Changes are checked against your apps

- **What is checked:** a change to your prices, your listed paths or the base
  URL, and adding a connection with a slug apps already name. The gateway checks
  the affected calls your active apps can still make.
- **What is refused:** a save after which the gateway can't price one of those
  calls fully, with `400 pricing_not_configured`, naming the app and the model.
  That includes a model an app lists by name, a preset's first target and a
  preset's [fallback](/applications/custom-endpoints#fallbacks), which would
  otherwise drop out of its chain without a word.
- **What still saves:** removing a price or a path that leaves the call no
  longer allowed, such as a model's price on an app with no models list. Those
  requests are then refused when made.

## Errors your apps may get

| Answer | Meaning |
| --- | --- |
| `502 provider_not_configured` | The app does not allow a connection with this slug, or no connection has it. |
| `502 provider_disabled` | The connection is turned off. Turn it on. |
| `502 provider_unavailable` | The connection cannot be used as stored, for example its key could not be opened. |

The gateway's errors, and how to handle them, are in [Errors and limits](/integrate/errors).

## How keys are kept safe

- Each key is encrypted before it is stored, tied to its connection and to the
  place it is sent. A key never goes to a new host unless you type it again for
  that host. The one exception is going back to the provider's own host, when
  you ask for it.
- No answer from the gateway contains a key.
- Your apps never see a key. The gateway adds it on the way to the provider,
  and never forwards a key header an app sends. See
  [Calling the provider proxy](/integrate/proxy#what-reaches-the-provider).
- A coding agent never needs your key. It can open a page where you type the
  key into the console yourself.
