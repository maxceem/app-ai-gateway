---
title: Cloudflare and Vercel AI Gateway
description: Send a connection through your Cloudflare AI Gateway, or add Vercel AI Gateway as a provider.
---

You can put another AI gateway between this gateway and the providers. The two
work differently:

- **Cloudflare AI Gateway** is a setting on a connection. The connection keeps
  its provider, operations, paths and prices. Its requests go through your
  Cloudflare gateway on the way to the provider.
- **Vercel AI Gateway** is a provider of its own. One connection reaches the
  models of many providers through Vercel.

Both are optional. A connection with its own key goes straight to the provider.

## Cloudflare AI Gateway

A connection to OpenAI, Anthropic, xAI, Gemini or Perplexity can go through
your Cloudflare AI Gateway. Cloudflare passes each request to the provider, and
passes the provider's answer back as it is.

### Turn it on

When you add the connection, tick **Send through Cloudflare AI Gateway** and
fill in:

| Field | What to enter |
| --- | --- |
| **Cloudflare account ID** | Your Cloudflare account's ID. |
| **Cloudflare gateway ID** | The name of your gateway in Cloudflare. |
| **Cloudflare token** | Your gateway's authentication token. Stored encrypted, and never shown again, only its last characters. |
| **API key** | Optional. Leave it empty to use the provider keys stored in your Cloudflare gateway. |

Each ID may hold only letters, digits, `-`, `_`, `.` and `~`, such as `my-gateway`. **Test key** sends its
test call through your Cloudflare gateway, so it checks the IDs, the token and
the provider key together.

For a connection you already have, open its **Cloudflare AI Gateway** action.
The same fields appear, plus:

- **Use the keys stored in Cloudflare, and remove this connection's key.**
- When the connection has a base URL, **Remove the base URL …**. You must tick
  it, because a connection goes either to a base URL or through Cloudflare.
- Once it is on, **Stop using Cloudflare AI Gateway**.

A key goes only where it was given. So turning Cloudflare on, or moving to
another account or gateway, needs the provider's key again, or the box that
uses Cloudflare's stored keys. Changing only the token, for the same account
and gateway, keeps the key.

To stop, click **Stop using Cloudflare AI Gateway**, enter the provider's key
for its own host, and click **Go direct**. A key is never moved there from
Cloudflare.

The same through the API:

```http
PUT /v2/admin/providers/{id}
Content-Type: application/json

{
  "cloudflareGateway": { "accountId": "…", "gatewayId": "my-gateway", "token": "…" },
  "secret": null,
  "revision": 7
}
```

- `secret: null` uses Cloudflare's stored keys. Send a key instead to keep one.
- `token` may be left out to keep the stored one, for the same account and
  gateway.
- `cloudflareGateway: null` stops, and needs `secret` in the same request.
- A connection with a base URL keeps it unless you send `baseUrl: null` in the
  same request. Send it when you turn Cloudflare on there, or the request is
  refused: a connection cannot have both. The console's box does this for you.

### What changes on the way

Your apps call the same URLs, with the provider's own paths, as on a direct
connection. The gateway sends each request to
`https://gateway.ai.cloudflare.com/v1/{account}/{gateway}/` and Cloudflare's
own name for the provider: `openai`, `anthropic`, `grok` for xAI,
`google-ai-studio` for Gemini, or `perplexity-ai`. Cloudflare's OpenAI route
leaves out the leading `v1/`, so an app's `v1/responses` on OpenAI is sent to
`https://gateway.ai.cloudflare.com/v1/{account}/{gateway}/openai/responses`.
The gateway adds:

- `cf-aig-authorization`, your Cloudflare token;
- `cf-aig-metadata`, the app's ID and, when known, the user's ID, so Cloudflare's
  logs show who made each request;
- the provider's key in the provider's own header, when the connection keeps
  one.

An app may send Cloudflare's own controls, which are passed on:
`cf-aig-cache-ttl`, `cf-aig-skip-cache`, `cf-aig-max-attempts`,
`cf-aig-backoff` and `cf-aig-retry-delay`. No other `cf-aig-` header is.

Because Cloudflare passes the provider's answer back unchanged, prices and
reported costs work as on a direct connection. **Replace key** has no
**Test key** on such a connection.

## Vercel AI Gateway

Add it like any provider: choose **Vercel AI Gateway** and paste a Vercel AI
Gateway API key. **Test key** calls Vercel's `v1/credits`, which needs a real
key.

It has three operations, whatever model you call:

| Operation | Path |
| --- | --- |
| `vercel.chat` | `v1/chat/completions` |
| `vercel.responses` | `v1/responses` |
| `vercel.messages` | `v1/messages` |

### Model names and prices

A model is named as Vercel names it, with its maker first, such as
`openai/gpt-5.4-mini`. Use that name in the app's models list and in requests.

Vercel answers in its own words, so no provider's reported cost comes through.
Each request is billed from the price list, under the provider its maker names:

| Maker in the model name | Priced as |
| --- | --- |
| `openai/` | OpenAI |
| `anthropic/` | Anthropic |
| `google/` | Gemini |
| `spacexai/` | xAI |
| `perplexity/` | Perplexity |
| `deepseek/` | DeepSeek |
| `moonshotai/` | Moonshot AI |

So `google/gemini-3.5-flash` costs what Gemini's `gemini-3.5-flash` costs. A
model of any other maker needs [your own price](/providers/model-pricing#your-prices)
on the connection, under its full name.

Vercel's own tier fields, such as `providerOptions.gateway.serviceTier`, are
read to bill the request in the right [service mode](/providers/model-pricing#service-modes).

### Vercel's fallback models

A request may name other models in `providerOptions.gateway.models`, for Vercel
to try when the first cannot serve. Each must pass the app's models list and
have a price, or the request is refused before it is sent. It is billed at the
model that served it. On a [preset](/applications/custom-endpoints), only the
preset's own model may be named there.

### Choosing which providers serve

Vercel may serve one model from several providers. To pin the providers it may
use, set `servingProviders` on the connection through the API. The gateway sends
them as `providerOptions.gateway.only` on every request, over any value the app
sends. Vercel checks the names. `null` stops pinning.

```http
PUT /v2/admin/providers/{id}
Content-Type: application/json

{ "servingProviders": ["anthropic", "vertex"], "revision": 7 }
```

### Spend reports in Vercel

The gateway sets Vercel's `ai-reporting-tags` to `app:{app}` and
`ai-reporting-user` to the user's ID, when it is known and Vercel accepts it.
An app cannot set these headers itself, so Vercel's own spend reports name the
real app and user.
