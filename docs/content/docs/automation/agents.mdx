---
title: Use with AI agents
description: Connect an agent to your account, let it set up and check apps, and keep keys out of its view.
---

An agent can add providers, set up your apps, write the code that calls them
and look into usage and failures. You stay in charge of secrets: you type
provider keys in your own browser, and see new app keys on a page or in a
private file, never in the conversation.

## Choose how to connect

| Your agent can use | Start here |
| --- | --- |
| A terminal in your project | The [CLI](/automation/cli). It writes a server app's key to a private file. |
| A remote MCP server | Add `https://console.appaigateway.com/v2/mcp` to the client and approve it in your browser. See [MCP server](/automation/mcp). New app keys are shown to you on a page. |
| Only HTTP requests | The [management API](/automation/api), with a management key from your secret store. |

For a review or an investigation, give the agent the **Read only** grant: on
the approval page when the CLI or an MCP client signs in, or when you create a
management key. Give it **Manage** when it should change things.

<Callout title="Self-hosting">
  Use your console's address followed by `/v2/mcp`, or connect the CLI with
  `agw deployment connect --url https://YOUR-CONSOLE`.
</Callout>

## Give the agent a task

With the CLI installed, give your coding agent a prompt like this one, with
your own task on the last line:

```text
Read https://docs.appaigateway.com/agents.md, then use agw for this task.
Check which gateway and account agw is signed in to first. If it is not signed
in, run agw account login --no-open --json --no-input as a background process,
or in a session that shows its output as it runs: it waits up to ten minutes.
Read the link and code it prints on stderr as soon as they appear, and give
them to me to approve.
Read the existing providers and apps, use --json --no-input, and validate
changes before saving them. If a provider is missing, tell me which one and
stop: I will add its key myself, then you carry on. Never print secrets. Keep
app keys in private files.
Finish with app check and app snippet. Do not send AI requests unless I ask.
Report the app ID, the URLs my app calls, the changes, and what is left to do.
Task: set up an iOS app for Team ID ABCDE12345 and Bundle ID com.example.app.
```

Over MCP, give the same task, and ask the agent to read `agw://guide`, start
with `get_account`, and finish with `check_app` and `get_app_snippet`.

Other tasks that work well:

- "Review this app's providers and limits, and suggest changes."
- "Add a preset so I can change models without releasing my app."
- "Explain this app's recent failures from its sign-in events and refusals."

## Use your account

The agent works in an account you already have. Signing in never creates one:
create your account in the console first, or on the sign-in page that opens.

With the CLI, the agent runs `agw account login --no-open`, which prints a link
and a short code and waits up to ten minutes. Open the link yourself, check the
code matches, choose the account and the grant, and approve. The agent never
sees your password or your console session.

## Provider keys

When a provider is missing, add its key yourself, then let the agent carry on:

- on the console's **Providers** page, with **Add provider**; or
- on your own machine, with `agw provider add --type openai`, which asks for the
  key in a hidden prompt, or reads it from stdin with `--key-stdin`.

The agent then finds the new connection with `agw provider list`.

When the agent runs on your own machine, it can instead run
`agw provider add --type openai --browser --json`. If you want that, say so in
the prompt. If `agw` says a browser window opened, type the key there; the
agent then waits with `agw operation wait <id>`. If `agw` saved the link to a
file instead, the agent falls back to asking you to add the key yourself.

Over MCP, `add_provider` answers a console link for you to open, and the agent
waits with `get_operation`.

Do not paste provider keys into the conversation. A hidden terminal prompt keeps
a key off the screen, but not away from an agent that controls the terminal.

For a CI job with no person present, put a management key in the job's secret
store as `AGW_MANAGEMENT_KEY`. Never paste it into a command or a chat.

## Check the result, and end access

The agent should report what it changed, the IDs and slugs, the URLs your app
calls, where any key was saved, and what is left to build.

`app check` and `check_app` look at the settings without calling a provider.
They do not test a provider key, a device, a user's sign-in or a subscription,
so a good check is not an end-to-end test.

A command or tool that answers `state: "pending"` is waiting for you; it has not
finished. The console's **Access** page lists the agent's CLI sign-in, MCP
connection or management key. Revoke it there when the agent's work is done.
`agw account logout` also ends the CLI's sign-in.

## Machine-readable instructions

- [Agent manual](/agents.md): the workflow, the rules and the app settings
