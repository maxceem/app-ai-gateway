---
title: Agent integration
description: A deterministic workflow for agents deploying and configuring the gateway.
---

Agents should treat checked-in schemas and command output as authoritative. Do not
infer production configuration from project-specific examples.

## Safe workflow

1. Inspect the target application's identity provider and runtime.
2. Choose App Attest or API-key client proof, then decide whether the app needs issuer-backed user identity.
3. Produce a candidate application JSON document. It carries `name`, `config` and
   an optional `status` — never `id`, which the gateway assigns and a create
   request that sends one is refused with `400`.
4. Validate it before applying it.
5. Confirm Cloudflare authentication and required secrets without printing values.
6. Perform a deployment dry run when available.
7. Deploy, call `/v1/healthz`, and confirm the application through the admin API.
8. Return the gateway URL, application ID, and non-secret client configuration.

The application ID is the server's: read `app.id` from the create response and
use that exact value in every later URL. It cannot be chosen or changed, and
`PUT /v1/admin/apps/{app}` only updates an application that already exists.

## Machine-readable sources

- `openapi/openapi.json` is the generated HTTP contract.
- `src/contracts/schemas.ts` contains shared runtime schemas; `src/contracts/openapi.ts`
  assembles them into documented operations.
- `.dev.vars.example` names the one required secret without a value and keeps
  every optional name commented out: the Deploy to Cloudflare form masks each
  uncommented name here and shows each `wrangler.jsonc` `vars` entry in clear
  text, so a setting belongs in exactly one of the two.
- `wrangler.jsonc` declares Cloudflare resources; gitignored
  `wrangler.<profile>.overlay.jsonc` files hold deployment-specific overrides.

## Secret rules

- Never place secrets in command arguments, source, documentation, or chat output.
- Use hidden prompts, stdin, ignored files, or a secret manager.
- Treat initial application API keys as one-time outputs.
- Report where a credential was stored rather than repeating its value.
