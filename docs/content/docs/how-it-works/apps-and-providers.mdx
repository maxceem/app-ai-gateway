---
title: Apps and providers
description: The two things you set up, what each one owns, and how a request moves between them.
---

You set up two kinds of things in the console. **Providers** are the AI
services you hold keys for. **Apps** are the applications that call them. A
call through the provider proxy names one app and one provider:

```text
https://api.appaigateway.com/v2/apps/{app}/proxy/{provider}/{provider_path}
```

A call to a [preset](/applications/custom-endpoints) names the app and the
preset instead, and the preset names the provider:

```text
https://api.appaigateway.com/v2/apps/{app}/presets/{preset}
```

## Providers are shared, apps choose

You add a provider key once, as a **provider connection**, and every one of your
apps can use it. You do not add the same OpenAI key to each app.

Each connection has a **slug**, the `{provider}` part of the URL above. The first
connection of a provider can take the provider's own name: `openai`,
`anthropic`, `gemini`. A second key of the same provider needs a slug of its
own, such as `openai-dev`, so an app can name one key or the other. See
[Add a provider key](/providers/add-a-provider).

A new app may call nothing. On its **Providers** tab you choose which
connections it may use. For each one you choose which **operations** it may use,
such as `openai.chat` or `anthropic.messages`, and, if you want, which models.

Each app has its own settings, one tab each:

- **Sign-in**: how the app proves it is your app, whether calls belong to
  signed-in users, and whether those users must have paid.
- **Providers**: which connections, operations and models it may use, and the
  most output tokens a request may ask for.
- **Rewrites**: model names the gateway changes to others on the way through.
- **Presets**: named requests whose connection, model and settings live on the
  gateway.
- **Limits**: requests per minute and per day, and a monthly budget, for each
  user and for the whole app.
- **Settings**: the app's name, turning it on or off, and deleting it.

## The app ID is permanent

The gateway builds an app's ID from its name and a short random ending, for
example `example-app-a1b2c3`. The ID is the `{app}` part of every URL the app
calls, so your app builds it into its base URL. You cannot choose it or change
it. Renaming the app, on its **Settings** tab, changes only the name. An ID is
never given to another app, even after the app is deleted.

The ID is not a secret. Knowing it lets nobody call the app: App Attest or an
app key still has to pass.

## What happens to a request

1. The gateway reads the app from the URL and checks who is calling. An iOS app,
   and a server app with signed-in users, sends a gateway token. A server app
   without signed-in users sends its app key.
2. It works out which user the call belongs to, if the app has users, and
   refuses a user you blocked.
3. It checks what the call asks for. On the provider proxy: is this connection
   allowed, this operation, this model? On a preset: does the preset exist? And
   does the model have a price, so the cost can be counted?
4. It checks the app's limits: each user's first, then the app's.
5. It adds your provider key and sends the request to the provider. The body
   goes through as you sent it, apart from a few changes in the same format,
   such as a model rewrite or an output cap you set.
6. The provider's answer streams back to your app as the provider sent it. The
   gateway reads the usage from it and records one **charge**: its tokens,
   cost and outcome.

A request refused before step 5 never reaches a provider and costs nothing.
The app's **Usage** tab shows the charges. The **Errors** tab shows sign-in
failures and sampled requests the gateway refused; those samples are not
usage.

## Provider-native, not unified

The gateway does not have a request format of its own. You send OpenAI's body
to an OpenAI connection and Anthropic's body to an Anthropic connection, and
you get each provider's own answer back. The provider's documentation stays the
reference for every field.

This is what lets the official SDKs work as they are. Point the OpenAI SDK's
base URL at `…/proxy/openai/v1` and it adds `responses` or `chat/completions`
itself. See [Calling the provider proxy](/integrate/proxy).

## When changes take effect

In normal operation:

- A saved change to an app, a new or revoked key, a connection turned off, an
  app turned off or deleted: each reaches every request within a minute.
- Blocking or unblocking a user reaches every request within ten seconds.

The exception keeps your apps' users served when the database behind the
gateway is slow or down. While it is, the gateway may serve a request with the
copy of the app's settings, keys and user status it last read, up to fifteen
minutes old. So a change you make during such a problem can take up to fifteen
minutes to reach every request.

Even then, a new gateway token is issued only after the app key and the user's
status are read fresh. So a revoked key or a blocked user cannot get a new token.
The app's other settings may still come from the saved copy, for a new token as
for any other request.
