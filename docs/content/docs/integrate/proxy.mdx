title: Calling the provider proxy
description: The URL, the headers, what reaches the provider, streaming, and the limits on one request.
---

The provider proxy sends a provider's own request to one of your provider
connections:

```text
{METHOD} https://api.appaigateway.com/v2/apps/{app}/proxy/{provider}/{provider_path}
```

- `{app}` is the app's ID.
- `{provider}` is a connection's slug, such as `openai` or `openai-dev`. It
  names one of your keys, not a provider.
- `{provider_path}` is the provider's own path, without a leading slash, such
  as `v1/responses`. The paths of each provider are in
  [Supported providers](/providers/supported-providers).

The body is the provider's body, and the answer is the provider's answer. The
provider's documentation is the reference for both. The app must allow the
connection and the operation on its [Providers tab](/applications/provider-access).

## Headers your app sends

| Header | When |
| --- | --- |
| `Authorization: Bearer <app key>` | A server app with no signed-in users. |
| `Authorization: Bearer <gateway token>` | An iOS app, or a server app with signed-in users. See [What the gateway token is](/how-it-works/identity#what-the-gateway-token-is). |
| `X-App-Version` | With a gateway token: your app's version, such as `1.4.2`. A request without it is refused with `400 invalid_request`. |
| `X-AppAttest-Proof` | An iOS app that checks App Attest on every request. See [Per-request proof](/integrate/ios#4-sign-each-request). |
| `X-End-User-ID`, or the header you named | A server app that sends the user ID itself. See [User authentication](/applications/auth-policy/user-authentication#your-server-sends-the-user-id). |
| `X-Client-Trace-Id`, `X-Conversation-Storage: off` | Optional. See [Conversation history](/applications/conversations). |

The app key or gateway token may also go in the provider's own key header, such
as Anthropic's `x-api-key` or Gemini's `x-goog-api-key`, and `Bearer` is
optional there. That is what lets a provider's SDK send it as its key.

None of these headers reaches the provider.

## Using an SDK

Set the SDK's base URL to the proxy URL up to the provider's version prefix, and
give it your app key or gateway token as its key. The SDK adds its own paths:

```python
from openai import OpenAI

client = OpenAI(
    api_key=gateway_credential,
    base_url="https://api.appaigateway.com/v2/apps/example-app-a1b2c3/proxy/openai/v1",
)
```

More base URLs are in [Supported providers](/providers/supported-providers#using-an-sdk).

## Model names

Send the provider's own model name, as on
[the app's models list](/applications/provider-access#models). If the app has a
[model rewrite](/applications/model-rewrites) for the name, the gateway changes
it on the way.

## Streaming

Ask for a stream the provider's own way, such as `"stream": true`, or Gemini's
`:streamGenerateContent` path, and read it as the provider documents. The
gateway passes it on as it arrives, and reads the usage as it goes by. If your
app disconnects during the stream, the gateway stops reading it from the
provider.

A streamed Chat Completions answer reports usage only when the request asks for
it. So on every Chat Completions request with `"stream": true`, the gateway
sets `stream_options.include_usage` to `true`, and keeps your other stream
options. The stream then ends with one more chunk before `[DONE]`: its
`choices` is empty, and it carries `usage`. The OpenAI SDKs handle it. If you
read the stream yourself, do not assume `choices[0]` exists.

## Transcription

A transcription is charged by the tokens or the length of audio its answer
reports. A plain-text answer reports neither. So on OpenAI, Groq and Together
AI:

- a transcription names `response_format` at most once;
- on OpenAI, `text`, `srt` and `vtt` are refused with `400 invalid_request`.
  Use `json`, the default, or `verbose_json` or `diarized_json`;
- Groq and Together AI report the length only in `verbose_json`. A request for
  `json`, or for no format, is sent as `verbose_json`. The answer still has the
  same `text` field, plus timings. Other formats are refused.

## What reaches the provider

The gateway adds your provider key, and sends on only these headers from your
app:

- `content-type`, `accept`, `accept-language`, `user-agent`;
- `anthropic-version`, `anthropic-beta`,
  `anthropic-dangerous-direct-browser-access`, `openai-beta`,
  `x-goog-api-client` and `idempotency-key`;
- headers starting with `x-stainless-`, which the OpenAI and Anthropic SDKs
  send.

A header among these whose name has a word such as `key`, `token`, `secret`,
`auth` or `session` is still dropped, except `idempotency-key`. Every other
header is dropped. So a provider never sees your user's cookies, a provider
key your app sent, or a header that would charge another account, such as
OpenAI's account and project headers.

Two more kinds go through where they apply:

- on a [passthrough path](/applications/provider-access#passthrough), the
  headers its provider needs there, such as Gemini's `x-goog-upload-` headers;
- through Cloudflare AI Gateway, its caching and retry controls. See
  [What changes on the way](/providers/gateways#what-changes-on-the-way).

On the way back, the provider's headers pass through, except `set-cookie`,
OpenAI's account and project headers, the header the key was sent in, and
the length and encoding headers that no longer fit once the body is streamed
again. `x-request-id` is kept, because provider support asks for it.

The gateway adds `Server-Timing`, with the time each step took: `auth`,
`prepare`, `limiter` and `provider_ttfb`, the provider's time to its first
byte. A step the request never reached is left out.

## Service modes

Some providers serve a request faster, cheaper or in a chosen region for
another price, chosen by a field in the body, such as OpenAI's `service_tier`,
Anthropic's `speed` and `inference_geo`, or Gemini's `service_tier`. Send it in
the provider's own format. The gateway sends it on as it is, and reads it to
price the request. See [Service modes](/providers/model-pricing#service-modes).

## Limits on one request

- A body is at most 20 MiB. A larger one is refused with
  `413 payload_too_large`.
- The provider has 120 seconds to send its response headers, or the request is
  answered with `504 provider_error`. On an ordinary call, there is no time
  limit once they arrive. Deepgram has 20 minutes. Self-hosted gateways can
  change the 120 seconds.
- [Jobs](/applications/jobs) have their own limits. A job submission the
  provider accepted has 30 seconds to send its body with the job ID, and a job
  check waits 30 seconds for the provider's response headers. Either answers
  `502 provider_error` when it runs out.
- **Most output tokens**, if the app sets it, refuses a request that asks for
  more. See [Most output tokens](/applications/provider-access#most-output-tokens).
- A request that asks the provider to run in the background is refused. See
  [Operations](/applications/provider-access#operations).

## Provider errors

A provider's own error, such as a `400` for a bad body or a `429` from its rate
limit, is passed to your app with the provider's status and body. A request the
gateway could not deliver is answered with `502 provider_error` in the
gateway's own format. See [Errors and limits](/integrate/errors).

The gateway never follows a redirect from the provider.

## Where a user stands

An app that names its users can call `GET /v2/apps/{app}/me` with the same
headers, `X-App-Version` aside. See
[What a user can see about themselves](/how-it-works/limits#what-a-user-can-see-about-themselves).
