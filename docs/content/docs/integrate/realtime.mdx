---
title: Realtime voice
description: Talk to OpenAI's realtime models over a WebSocket through the gateway, with every response counted, limited and recorded per user.
---

Your app can hold a live voice or text conversation with OpenAI's realtime
models through the gateway. The app opens a WebSocket to the gateway, and the
gateway connects to OpenAI with your provider key. Your app never holds that
key, and the conversation follows the same rules as every other request:

- The gateway checks your app's authentication before the conversation opens:
  App Attest, sign-in tokens and paid-user checks, as for any request.
- The limits you set per user and per app apply: requests per minute and per
  day, and the monthly spending budget.
- Every response is counted as one request, and its usage and cost are recorded
  against the user, so you see realtime traffic in the console with the rest.

Events on the socket are OpenAI's own realtime events, so OpenAI's realtime
documentation applies. The gateway adds a few rules, described below.

## What is supported

| Provider | Models | Features |
| --- | --- | --- |
| OpenAI, direct or through Cloudflare AI Gateway | `gpt-realtime`, `gpt-realtime-mini` | Text and 24 kHz PCM audio, manual turns or voice detection (`server_vad`), function tools that run in your app |

Gemini Live is not available yet. Other provider gateways, such as Vercel AI
Gateway, and custom provider addresses don't support realtime. Through
Cloudflare AI Gateway, the conversation uses the OpenAI key stored in your
Cloudflare gateway.

Not supported: images, input transcription, hosted tools, stored prompts,
semantic voice detection, and binary frames. Browsers and WebRTC aren't
supported, because a browser can't send the authentication headers a
WebSocket needs. Use a native app or a server.

## Turn it on

Realtime is off for every app until you turn it on.

1. In the console, open your app's **Settings** and, under **Realtime
   sessions**, turn on **Enable realtime WebSockets**. You can also lower the
   session length and the number of open sessions per app and per user there.
2. In **Provider access**, allow the OpenAI provider. If you list endpoints
   for it, add `v1/realtime`. If you list models, add the realtime models
   you use.

The built-in price list prices `gpt-realtime` and `gpt-realtime-mini`. A custom
price for a realtime model must give text input and output, audio input and
output, cached text input and cached audio input.

Through the API, the CLI or MCP, set the app's `realtime` settings:

```json
{
  "realtime": {
    "enabled": true,
    "max_session_seconds": 1800,
    "max_concurrent_sessions": 10,
    "max_concurrent_sessions_per_identity": 2
  }
}
```

## Connect from an iOS app

Use the AppAIGateway Swift package 1.9 or later.
`authorizedRealtimeRequest` finds the conversation's address and builds a
signed handshake for it. Build a new one for every conversation.

```swift
let request = try await gateway.authorizedRealtimeRequest(
    provider: .openai, model: "gpt-realtime"
)
let socket = URLSession.shared.webSocketTask(with: request)
socket.resume()

// Wait for session.updated before sending input.
while true {
    let message = try await socket.receive()
    guard case .string(let text) = message else { continue }
    let data = Data(text.utf8)
    if let error = try? JSONDecoder().decode(RealtimeGatewayError.self, from: data),
       error.type == "gateway.error" {
        print(error.error.code) // See "When a conversation ends" below.
        break
    }
    // Handle OpenAI's event, and send yours when appropriate:
    // try await socket.send(.string(#"{"type":"response.create"}"#))
}
socket.cancel(with: .normalClosure, reason: nil)
```

On an app that verifies App Attest on every request, the package signs both
requests a conversation opens with: finding the address, and the handshake.
Nothing sent over the open socket is signed.

## Connect from a server

A conversation opens in two steps.

1. Ask the gateway where to connect. Use your provider's slug, `openai` in
   this example, and the model:

   ```text
   GET https://api.appaigateway.com/v1/apps/{app}/realtime/openai/connection?model=gpt-realtime
   Authorization: Bearer <your app API key or gateway token>
   ```

   The answer is `{ "url": "wss://…", "releaseId": "…" }`.

2. Open that `url` as a WebSocket with the same headers:

   ```js
   import WebSocket from "ws";

   const base = "https://api.appaigateway.com";
   const headers = { Authorization: `Bearer ${process.env.APP_API_KEY}` };
   const found = await fetch(
     `${base}/v1/apps/${appId}/realtime/openai/connection?model=gpt-realtime`,
     { headers },
   );
   const { url } = await found.json();
   const socket = new WebSocket(url, { headers });
   socket.on("message", (data) => console.log(JSON.parse(data)));
   ```

Send `X-App-Version` with gateway tokens, and your end-user header if your
app identifies users that way. Credentials in the URL, in cookies or in
WebSocket subprotocols are refused. Ask for the address again for every new
conversation, and when an open is refused with `conflict`.

## How a conversation works

The gateway checks everything when the conversation opens: authentication,
your app's settings, and the limits you set per user and per app. After that,
turns never wait for the gateway. Each response goes to OpenAI at once and is
counted in the background.

- **Each response is one request.** Twenty responses in one conversation count
  as twenty requests. Opening the conversation, configuring it, audio and
  output add none. A failed, cancelled or interrupted response still counts.
- **A limit reached ends the conversation.** If counting a response finds a
  limit reached, the user blocked or the app's access changed, that response
  finishes, uncounted, and then the conversation closes with a `gateway.error`.
  So a limit can be exceeded by one response per open conversation, or a few
  more while the gateway is slow to answer.
- **Usage is never lost.** Each response's usage is stored before its last
  event reaches your app, then recorded in the background. If the gateway
  can't record it for a moment, the conversation goes on and the usage is
  recorded once it can. A spending budget can lag by a response.
- **Audio and conversations aren't stored.** Raw audio, transcripts and keys
  are never kept, only usage.

### OpenAI events

Wait for `session.updated` before sending input. The gateway starts every
session with voice detection off.

- **Manual turns:** send conversation items or append and commit audio, then
  `response.create`.
- **Voice detection:** send `session.update` with
  `audio.input.turn_detection.type` set to `server_vad`. With
  `create_response` left on, the gateway starts one response for each
  utterance; don't send `response.create` yourself. Speech that arrives while
  a response is running is answered by one response after it. With
  `create_response: false`, voice detection only commits your audio, and you
  send `response.create`.
- **Interruptions:** under voice detection, when the user starts speaking, the
  gateway cancels the running response, unless you set `interrupt_response`
  to `false`. Upstream, OpenAI's own automatic responses and interruptions are
  always off, because the gateway applies them; `session.updated` shows the
  settings OpenAI received.
- **Function tools** run in your app. Send each result with
  `conversation.item.create`, then ask for another response.
- **Cancelling:** `response.cancel` stops the running response. It costs no
  extra request, and the response still counts.
- **Output length:** you may lower `max_output_tokens`. The gateway caps every
  response at 4,096 tokens, or your app's lower limit.

Only one response can run at a time. A `session.update` while a response is
running, an unknown event or field, or an event ID reused with different
content closes the conversation.

## Limits

| Limit | Default |
| --- | --- |
| Conversation length | 30 minutes, or the sign-in token's expiry if sooner |
| Open conversations | 10 per app, 2 per user (an install on an iOS app, an API key on a server app with no users) |
| Responses per conversation | 1,000 |
| Idle time | 2 minutes without useful activity |
| One turn's input | 60 seconds, 4 MiB |
| One response | 2 minutes, 16 MiB of output |
| Setup | 10 seconds |
| Frames | 256 KiB from your app, 1 MiB from OpenAI |
| Input rate | 256 KiB a second (four times live 24 kHz audio), bursts to 1 MiB |
| Opening | 30 address lookups and 10 conversations per user a minute |

Under voice detection, only audio sent while OpenAI hears speech counts toward
a turn's input, so a microphone streaming silence between turns doesn't use it
up.

## When a conversation ends

The gateway reports its own errors as a `gateway.error` event, then closes the
socket. OpenAI's events, errors included, reach your app unchanged.

```json
{
  "type": "gateway.error",
  "error": { "code": "app_rate_limited", "message": "Request limit exceeded", "retry_after_seconds": 30 },
  "session_id": "server-generated-session-id",
  "generation_id": "server-generated-generation-id"
}
```

| Close code | Means |
| --- | --- |
| 1000 | The conversation ended normally, or reached its maximum length |
| 1008 | A rule or a limit: see the `gateway.error` code |
| 1009 | Input or output too large |
| 1011 | OpenAI or the gateway failed |

An OpenAI `error` event also closes the conversation, after your app has
received it. The one exception is the error OpenAI sends when a cancel crosses
its response's end, which changes nothing.

To continue, open a new conversation with a fresh request. A conversation
can't be resumed. Changes to your app, its provider or its keys take effect
within about 90 seconds, even in an open conversation.

Gateway updates can end open conversations too. A self-hosted gateway can keep
them open through updates with
[seamless realtime releases](/self-hosting/updating#seamless-realtime-releases).

## Instead of client secrets

Some apps let their users call OpenAI directly: they mint an OpenAI client
secret through the gateway, from the `v1/realtime/client_secrets` endpoint,
and connect to OpenAI with it. The gateway passes that request through, but
it sees nothing of the conversation that follows:

- its responses aren't counted, so per-user and per-app limits don't apply to
  them;
- its usage and cost aren't recorded, so they're missing from the console and
  from spending budgets;
- the app holds a live OpenAI credential while the conversation lasts.

Realtime through the gateway has none of these gaps. If your app mints client
secrets today, move it to the gateway's realtime conversations, then remove
`v1/realtime/client_secrets` from your app's provider access.
