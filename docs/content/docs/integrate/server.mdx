title: Server applications
description: Call the gateway from your server with an app key, point standard SDKs at it, and tie calls to your users.
---

A server app proves itself with an app key. The first key is shown when you
create the app, and you can make more on the app's **Keys** tab. Each is shown
once. Keep it in your server's secret manager and read it from the environment.
See [Server apps](/applications/auth-policy/identity#server-apps).

## The URL

```text
https://api.appaigateway.com/v2/apps/{app}/proxy/{provider}/{provider_path}
```

`{app}` is the app's ID, `{provider}` a connection's slug, and
`{provider_path}` the provider's own path. The app's **Overview** tab, under
**First requests**, shows requests your app can send today, ready to copy.

<Callout title="Self-hosting">
  Replace `https://api.appaigateway.com` with your gateway's API address. Keep
  the `/v2/apps/…` path.
</Callout>

## With no signed-in users

Send the key with every request:

```sh
curl https://api.appaigateway.com/v2/apps/search-service-k3f9x1/proxy/openai/v1/responses \
  -H "Authorization: Bearer $APP_AI_GATEWAY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"gpt-5.4-mini","input":"Say hello."}'
```

### Standard SDKs

Set the SDK's base URL to the gateway, up to the provider's version prefix, and
give it the app key where it expects the provider's key. The SDK adds its own
paths.

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["APP_AI_GATEWAY_KEY"],
    base_url="https://api.appaigateway.com/v2/apps/search-service-k3f9x1/proxy/openai/v1",
)
response = client.responses.create(model="gpt-5.4-mini", input="Say hello.")
```

```typescript
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  apiKey: process.env.APP_AI_GATEWAY_KEY,
  baseURL: "https://api.appaigateway.com/v2/apps/search-service-k3f9x1/proxy/anthropic",
});
const message = await client.messages.create({
  model: "claude-sonnet-5",
  max_tokens: 256,
  messages: [{ role: "user", content: "Say hello." }],
});
```

This works because the gateway also reads the key from the provider's own key
header, such as Anthropic's `x-api-key`. The key never reaches the provider: the
gateway sends your provider key instead.

## Your server sends the user ID

If the app's **Who may call** is **Your server sends the user id**, add the
header with your own ID for the user to every request, `X-End-User-ID` unless
you named another:

```http
Authorization: Bearer agw_…
X-End-User-ID: customer-123
```

A request without it is refused with `400 invalid_request`. With an SDK, set it
as a default header. The rules for the value are in
[User authentication](/applications/auth-policy/user-authentication#your-server-sends-the-user-id).

## Signed-in users

If **Who may call** is **Signed-in users only**, the key alone is not accepted
on requests. Trade it, with the user's sign-in token, for a gateway token, then
send the gateway token with `X-App-Version`:

```sh
curl https://api.appaigateway.com/v2/apps/search-service-k3f9x1/auth/token \
  -H 'Content-Type: application/json' \
  -d "{\"api_key\":\"$APP_AI_GATEWAY_KEY\",\"issuer_token\":\"$ID_TOKEN\"}"
# {"access_token":"…","expires_in":3600}

curl https://api.appaigateway.com/v2/apps/search-service-k3f9x1/proxy/openai/v1/responses \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H 'X-App-Version: 2.3.0' \
  -H 'Content-Type: application/json' \
  -d '{"model":"gpt-5.4-mini","input":"Say hello."}'
```

The body of `/auth/token` takes exactly `api_key` and `issuer_token`. The
gateway token lasts an hour and stands for one user. Keep one per user, and get
a new one before it ends, or when a request answers `401 auth_required`. A
refused trade answers with one of the codes under
[What the app sends](/applications/auth-policy/user-authentication#what-the-app-sends).

`X-App-Version` is your server's own version. The app's **Usage** tab can
group charges by it.

## Presets

A [preset](/integrate/endpoints) checks who is calling exactly as the proxy
does. This example is for a server app with no signed-in users. If your server
sends the user ID, add the end-user header. With signed-in users, send the
gateway token and `X-App-Version` instead of the key.

```sh
curl https://api.appaigateway.com/v2/apps/search-service-k3f9x1/presets/chat \
  -H "Authorization: Bearer $APP_AI_GATEWAY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"input":"Say hello."}'
```

## What to watch

- `429 app_rate_limited` and `429 app_budget_exhausted` carry `Retry-After` and
  `data.scope`. With the scope `app`, the whole app's limit is reached, and
  slowing down one user does not help. See
  [Refusals](/how-it-works/limits#refusals).
- `502 provider_not_configured` means the app does not allow the connection in
  the URL. Tick it on the app's **Providers** tab.
- `400 pricing_not_configured` means the model has no price. See
  [Model pricing](/providers/model-pricing).

The gateway's errors, and how to handle them, are in [Errors and limits](/integrate/errors).
